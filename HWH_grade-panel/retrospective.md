## 三、踩过 / 差点踩的坑

### 1. 数据结构推断错误（最大风险点）

拿到真实 `data.js` 前，我按 starter 的 TODO 注释推断出结构并生成了演示数据，结果真实数据有 3 处差异：

| 项 | 推断 | 真实 |
|----|------|------|
| 性别字段 | `"boy"/"girl"` | **`"男"/"女"`** |
| 科目 | 物理、化学 | **网页设计、数据库** |
| SUBJECTS 字段 | `{key,name}` | `{key,name,abbr,full}` |

若直接按推断写，头像样式会全部失效（`class="avatar boy"` 永远不命中，因为数据是「男」）。

**教训**：真实数据到位后必须重新校准 spec，而不是沿用推断版。补救成本低（只改了 spec 与一个映射函数），但如果直接开写代码，就要返工渲染函数。

**结论沉淀**：新增 `avatarClass(gender)` 做「中文性别 → 样式类」映射，把数据差异收敛在单个函数内，而不是散落在渲染逻辑里。

### 2. 验收数值必须手算核对

最初我在 tasks.md 里写错了三个关键锚点值：

| 项 | 错值 | 正确值 |
|----|------|--------|
| 班级总分 | 14937 | **7559** |
| 全班平均分 | 166.0 | **84.0** |
| 周诗涵总分 | 479 | **489** |

这三个数字直接写进了验收清单，如果没修正，人工测试会误判为“功能有 bug”。**验收标准里的每一个数字都必须能反推出来**（7559 ÷ 90 = 83.98 ≈ 84.0）。

### 3. 空列表除零（真实缺陷）

`renderStats` 首次实现时，搜索 0 结果会导致 `0 / (0 × 5) = NaN`，四张卡全部显示 `NaN`。

修复方式：函数入口判断 `list.length === 0` 直接写零值并 `return`。**这是本轮唯一由代码评审发现并修复的实际缺陷。**

### 4. 模板约束:只补函数体，不动绑定

模板已给出 200ms 防抖的 input 监听与按钮事件委托。曾考虑自己重写监听，但 spec 明确禁止，且模板写法（`closest` + `querySelectorAll` 切换 `active`）本身就是教学示范。**约束降低了风险，也让评审范围可控。**

## 四、做法有效的部分

1. **验收清单先行**：每个任务先写「浏览器里怎么验证」，编码时目标明确，避免了写完再想验收。
2. **数值锚定真实数据**：把周诗涵 489、孙博文 328、挂科 3 人等写进清单，人工测试有唯一答案，不用肉眼判断。
3. **单函数粒度任务**：每轮只改一个函数，出问题时定位范围极小（本轮 5 个任务都没出现连锁故障）。
4. **纯函数抽离**：`getTotal/getAvg/getFails` 被 4 处调用，修改一处即全局生效（空值处理、满分判定都受益）。

## 六、知识点清单（课堂对应）

- **数组方法**：`reduce` 求和、`filter` 筛选、`sort` 排序、`slice` 复制、`forEach` 遍历、`map` 映射
- **DOM 操作**：`createElement` / `appendChild` / `setAttribute` / `innerHTML` 清空 / `textContent` 安全写入
- **样式控制**：`className` 拼接与 `classList.add` 的取舍（静态类名拼接，状态类用 `classList`）
- **事件**：`input` 防抖、`click` 事件委托 + `closest`
- **注意点**：`sort` 会修改原数组 → 先 `slice`；`firstChild` 用于保留 `%` 的 span

## 七、Git 提交复盘（建议的分阶段提交）

本项目按“一个任务一个提交”切分，提交信息体现**做了什么 + 为什么**：

1. `feat: 补齐工具函数与统计卡渲染` —— 数据地基 + 首个可见产出
2. `feat: 实现学生卡片列表渲染` —— 核心 DOM 构建
3. `feat: 实现不及格预警列表` —— 筛选 + 排序渲染
4. `feat: 接入搜索与排序联动` —— 交互闭环
5. `docs: 补充 spec / tasks / 复盘文档` —— 文档收尾

好处：出问题可二分定位；评审时一个 commit 对应一个任务，范围清晰。

### 新增经验

1. **截图驱动的需求也要先对齐口径**：同一张图有 4 处行为无法从像素推断（平均分口径、筛选语义、圆圈数字含义、横幅触发条件），先问后做避免了 4 处潜在返工。
2. **数据注释不可尽信**：data.js 注释称"优秀 7 人"，但按注释自己声明的规则（平均≥85）实算为 8 人（漏列张明轩 90.2）。**规则 > 注释**，最终以用户确认的 A 规则为准并写入 spec 勘误。
3. **CSS 覆盖问题优先改源头**：新增 `.rank-grid` 三列规则时因原规则后定义被压，第一反应用 `!important`，评审中改回直接修改原规则——单一样式来源更干净。
4. **固定口径 vs 跟随口径的分层**：全班级模块（平均分/Top3/状元/横幅）放初始化一次性渲染，列表级模块（统计卡/卡片/预警）留 `refresh` 链内——调用位置即口径声明，比注释更可靠。
5. **优秀线常量早有伏笔**：模板预留的 `EXCELLENT_AVG = 85` 在 v1.0 标注"暂不使用"，v2.0 自然启用——读模板时留意未使用的常量，往往是后续等级的接口。
